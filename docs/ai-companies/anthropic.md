# Anthropic

基础模型 · 美国 · 核查 2026-11-05

Anthropic通过Claude应用和编码代理直接服务知识工作者，也通过模型接口供软件团队构建生成式应用；重点是文本、代码和图像理解如何进入可复核的工作流程，而非只比较模型榜单。

**业务入口：公开产品入口**。Claude、Claude Code与开发平台均有公开入口和收费说明；不同套餐及云渠道的额度、模型和功能可能不同，部分功能标注Beta。

公司与集团：Claude应用、Claude Code和模型平台作为Anthropic同一业务研究；在AWS或Google Cloud提供模型属于渠道关系，不据合作推定被平台收购。

地区口径：按Anthropic主要公司业务主体记录；实际产品支持地区、组织采购及云渠道另行核对。

[公司官网](<https://claude.com/pricing>) · [网页档案](https://romanagent.github.io/Roman/#ai/company/anthropic)

## 重点产品

### Claude / Claude Code 工作入口

应用 · 已公开提供

为个人和团队提供资料处理与内容工作入口，并用Claude Code把模型接入代码库、文件修改和命令执行；两类任务具有不同环境和验收要求。

目标用户：处理知识资料或需要开发和维护软件的个人与专业团队。

AI作用：模型理解文本、代码与图像等输入，编码代理读取项目并组织文件修改及工具执行；最终产物仍依赖环境、权限和用户确认。

使用与交付：通过网页、移动、桌面及编码工具入口交付，具体账号、套餐和功能支持需对应官方说明。

收费形式：提供有限免费及分层订阅，组织方案可能结合席位与用量；额度和高级功能并非所有套餐一致。

产品边界：自动修改代码不等于测试通过，跨工具执行需要适当权限；不同客户端和套餐功能存在差异，Beta项不能视为所有账户稳定开放。

### Claude 模型 API

平台 · 已公开提供

把文本、代码和视觉理解能力作为接口提供给开发者，支持在自有产品中生成内容、提取资料并构建工具参与的工作流程。

目标用户：开发企业应用、自动化服务和多模态软件的技术团队。

AI作用：模型根据上下文生成结果并支持工具相关能力，开发者可结合结构化输出和检索设计任务；接口本身不包含全部业务校验。

使用与交付：通过开发平台、SDK及相应云渠道调用，应用团队负责身份、工具、资料处理和结果展示。

收费形式：API采用对应模型及服务的用量收费，订阅与组织权益需按当前条款核对，不假设应用订阅覆盖所有开发调用。

产品边界：图像可分析不表示能精确读取所有图表或细节，长任务也可能失败；模型版本、云渠道和数据处理条件需持续检查，生产效果应自建评测。

## 需求与市场

### 事实｜同一模型体系提供成品与开发入口 · 官方资料

Claude有面向个人和组织的直接使用方案，开发平台则提供模型接口，Claude Code进一步把能力放进软件项目。相同模型品牌不意味着交付责任相同，消费者使用助手与工程团队构建应用需要分别评估；目录不把每种客户端或模型更新算作新公司。

依据：[Claude当前个人与组织方案](<https://claude.com/pricing>) · [Claude开发平台概览](<https://platform.claude.com/docs/en/intro>)

### 判断｜核心需求是把复杂资料转为可用产物 · 研究判断

用户可能需要整理长资料、修改文稿或完成跨文件开发，这些工作不只是得到一句答案。价值应看结果能否被继续编辑与验收，以及任务中反复补充上下文的负担；模型回答详细并不自动等于工作完成，也不能据个人展示推定全部职业都获益。

依据：[Claude开发平台概览](<https://platform.claude.com/docs/en/intro>) · [Claude Code当前概览](<https://code.claude.com/docs/en/overview>)

## 产品与工作流

### 事实｜Claude Code能读项目并执行开发操作 · 官方资料

官方概览描述Claude Code读取代码库、编辑文件和运行命令，并与终端、编辑器、桌面及网页等工具结合。这说明它参与实际项目流程而非只生成代码片段；项目依赖、可运行环境和用户授权仍由使用方管理，自动操作不会取消团队的审查与合并制度。

依据：[Claude Code当前概览](<https://code.claude.com/docs/en/overview>)

### 判断｜多入口的价值在任务持续性 · 研究判断

用户在本地、编辑器和远程入口之间切换时，关键是能否理解当前状态和继续同一个任务，而不只是入口数量。长任务中如果上下文、文件版本或授权不一致，就容易增加返工；研究应关注交接与恢复，并把演示顺利和持续可靠运行区分开。

依据：[Claude Code当前概览](<https://code.claude.com/docs/en/overview>)

## AI技术与依赖

### 事实｜模型支持理解与生成但并非无边界 · 官方资料

平台概览列出文本和代码生成、图像输入理解，以及结构化输出和工具相关能力。具体模态和限制仍应对应模型文档，不能把“视觉”理解成任何图片都能精确读取；API提供能力积木，应用还需要组织资料、限制操作并判定何时拒绝或转人工。

依据：[Claude开发平台概览](<https://platform.claude.com/docs/en/intro>)

### 验证｜评测应包含失败与不确定结果 · 待验证

样本应覆盖资料不足、矛盾描述、工具失败和需要修改原文件的情况，并记录模型是否保留不确定性。对于软件任务还要检查测试和回归，而不只看代码语法；本条没有执行基准或真实账号试验，不能把官方复杂任务描述当作本研究已验证的准确率。

依据：[Claude开发平台概览](<https://platform.claude.com/docs/en/intro>) · [Claude Code当前概览](<https://code.claude.com/docs/en/overview>)

## 竞争与替代

### 判断｜比较要区分助手与自建代理 · 研究判断

Claude应用与其他工作助手比较，Code与编码代理比较，API又与其他模型服务或自托管路线比较。把三者放在同一公司下有助于理解上下游，但不能用一种入口的优势概括全部产品；客户应先选择需要直接使用还是开发集成，再决定比较标准。

依据：[Claude当前个人与组织方案](<https://claude.com/pricing>) · [Claude Code当前概览](<https://code.claude.com/docs/en/overview>) · [Claude开发平台概览](<https://platform.claude.com/docs/en/intro>)

### 验证｜保留传统工具和人工基线 · 待验证

可以把同一任务交给现有脚本、模板流程和AI代理，记录完成时间、返工及人工检查量。规则稳定的工作未必需要模型，复杂资料任务也可能需要领域专家；选择应围绕可维护的结果，而不是把自动执行的步骤越多当作产品越成熟或越划算。

依据：[Claude Code当前概览](<https://code.claude.com/docs/en/overview>) · [Claude开发平台概览](<https://platform.claude.com/docs/en/intro>)
