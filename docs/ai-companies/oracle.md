在Fusion企业应用中把业务对象、知识和工具提供给AI代理，并通过Agent Studio构建、测试和发布工作流；面向企业员工及实施团队，重点是业务记录上的受控操作，而不是独立通用AI聊天服务。

## 重点产品

### Oracle Fusion AI 与AI Agent Studio

平台 · 已公开提供

在Fusion应用环境内配置代理及工作流，连接业务对象、文档和外部工具，并通过测试和发布流程提供给授权用户。

目标用户：使用Fusion财务、人力、采购和供应链应用的企业及实施团队。

AI作用：模型依据指令和主题调用业务工具，工作流可包含多个代理及人工批准；应用对象和原生权限提供上下文，但并不自动保证任务判断正确。

使用与交付：在适用Fusion版本中按访问要求启用Studio，配置工具、主题、凭据和用户权限，再测试并发布代理工作流。

收费形式：属于企业云应用及相关AI方案的采购范围，具体包含、资源和第三方服务费用按合同确认，本轮不推定所有Fusion客户免费无限使用。

产品边界：版本文档证明可配置能力，不代表营销页所有方向均已在客户租户开放；修改业务对象和发送信息需正确权限、测试及明确人工监督。

## 需求与市场

### 业务对象比通用答案更重要 · 研究判断

企业用户处理的往往是具体单据、人员和订单，单纯回答一般知识不能完成工作。Fusion内代理的需求是把意图对应到正确对象和操作，价值应看是否减少查找与重复输入，同时保持记录准确和责任可追溯。

依据：[Oracle Fusion AI当前方向与入口](<https://www.oracle.com/applications/fusion-ai/>)

### 异常处理需要清楚范围 · 研究判断

财务和供应链流程包含很多例外，代理可能帮助整理信息和推荐步骤，但不同企业规则未必一致。研究应先定义一类可验收任务，观察资料缺失和条件冲突时如何处理，不能把跨部门覆盖当作全部异常已自动解决。

依据：[Oracle Fusion AI当前方向与入口](<https://www.oracle.com/applications/fusion-ai/>)

## 目标用户

### 业务用户与配置人员分工 · 研究判断

日常员工需要清楚的查询和操作界面，实施团队则定义工具、主题及凭据。两者对产品的理解必须一致，尤其自然语言请求会触发什么动作要能够解释；不应让业务用户以为所有建议都已由组织审核。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

### 管理员和流程负责人参与 · 研究判断

代理访问业务对象需要原生权限与相应角色，流程负责人还要决定批准和例外路径。采用研究应同时观察授权、发布和后续维护，而不是只衡量业务用户发起一次请求的便利，避免实施责任在团队间被遗漏。

依据：[AI Agent Studio 26D概览](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/overview-of-ai-agent-studio.html>) · [AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

## 产品与工作流

### 从模板到可发布工作流 · 研究判断

Studio允许从预配置流程开始或自建代理，资源、主题和工具共同定义任务边界。合理流程应先检查模板是否适合当前业务，再进行测试和发布，不能把复制模板等同已经完成需求分析或获得生产使用批准。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

### 动作、批准与结果衔接 · 研究判断

修改记录、发送信息和调用外部工具会产生不同后果，应在工作流中设定适当批准与结果检查。研究建议测试部分成功、重试和回退，确保代理不重复执行或只在自然语言中宣称成功，而没有确认底层对象状态。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>) · [Oracle Fusion AI当前方向与入口](<https://www.oracle.com/applications/fusion-ai/>)

## AI技术与依赖

### 业务语义来自应用配置 · 研究判断

Fusion提供业务对象、知识和接口，能够让代理靠近真实流程，但其正确性仍取决于主数据和配置。技术评估应检查相似对象、权限差异与字段含义，不能把平台原生集成解释成无需验证的数据质量保证。

依据：[AI Agent Studio 26D概览](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/overview-of-ai-agent-studio.html>)

### 工作流与模型节点分开 · 研究判断

多个代理、工具和其他节点组成流程，模型判断只是其中一部分。测试应分别观察信息提取、条件分支、工具参数和外部响应，保留确定性校验；如果只检查最终回答，会难以定位哪个步骤引入错误。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

## 竞争与替代

### 与传统Fusion操作比较 · 研究判断

原有表单、报表和工作流已经完成许多任务，代理应证明它降低了定位和解释成本。比较需保留相同权限与业务规则，观察是否更少出错或返工，不能仅以聊天界面更短来判断优于熟练用户的传统操作。

依据：[Oracle Fusion AI当前方向与入口](<https://www.oracle.com/applications/fusion-ai/>) · [AI Agent Studio 26D概览](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/overview-of-ai-agent-studio.html>)

### 与外部代理平台比较 · 研究判断

外部平台可能更灵活地连接多种系统，Fusion内代理则更贴近应用对象和既有治理。选择应看实际系统组合及维护能力，不能把原生或开放作为单一优劣标准；跨平台任务仍要验证身份、凭据和结果一致性。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

## 体验与交付

### 让用户理解正在改什么 · 研究判断

自然语言操作需要清楚显示目标对象、预期动作和执行结果，避免同名记录或上下文切换造成误用。体验测试应包含撤销、修改请求与权限不足，观察用户是否能回到传统页面确认，而不只看一次顺畅的演示。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

### 开发到生产的可见差异 · 研究判断

构建者看到的工具和资料可能多于普通用户，测试环境成功不代表正式环境表现相同。发布前应按实际角色验证代理，检查凭据、数据和入口是否一致，并明确哪些失败需联系管理员而不是反复改提示。

依据：[AI Agent Studio 26D概览](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/overview-of-ai-agent-studio.html>) · [AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

## 风险与机会

### 业务写入放大模型错误 · 研究判断

模型若选错对象或误解条件，影响可能进入财务、人事或采购记录。产品机会在于把读写权限、批准和结果校验做成正常流程，证据不足时及时停止；不能依靠模型自我解释替代对底层记录的独立检查。

依据：[AI Agent Studio 26D入门](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/get-started.html>)

### 逐版本追踪真实交付 · 研究判断

企业AI产品变化快，目录和采购应记录采用的文档版本及租户实际可用性。后续验证需要检查升级前后关键任务与权限行为，不能把某次发布公告作为长期全部功能稳定的保证，也不能由演示数量预测市场成功。

依据：[Oracle Fusion AI当前方向与入口](<https://www.oracle.com/applications/fusion-ai/>) · [AI Agent Studio 26D概览](<https://docs.oracle.com/en/cloud/saas/fusion-ai/26d/aiaas/overview-of-ai-agent-studio.html>)
