## 重点产品

### Meta Model API / Muse Code

平台 · 已公开提供

为开发者提供Muse模型托管调用与终端编码代理，也提供部分开放权重路线；同一产品体系中不同模型和接口具有各自成熟度与授权边界。

目标用户：构建应用、研究模型或在项目中使用编码代理的软件团队。

AI作用：模型承担推理、代码与多模态处理，编码工具组织计划、编辑和命令执行；开放权重可另行部署但不自动包含托管服务全部功能。

使用与交付：通过API、命令行和权重下载等方式交付，托管与自运行路径的资源及管理责任不同。

收费形式：托管模型按token或对应模态单位收费，Muse Code另有订阅；部分Contributor模式以训练授权交换折扣。

产品边界：文档标注Muse Wonder为预览，不能将其当所有生产场景稳定承诺；Contributor涉及内容训练许可，企业代码和私人资料需先核对条件。

### Muse 个人任务代理

应用 · 已公开提供

通过专用云端工作环境持续处理个人任务，在应用或消息入口中接收目标并使用浏览器和连接器；需要用户选择授予哪些资料及操作权限。

目标用户：希望管理日常资料、计划和跨应用任务的个人用户。

AI作用：模型将自然语言目标转为计划和工具操作，云端虚拟机维持任务环境，并结合记忆及授权流程继续多步骤工作。

使用与交付：以个人代理应用及消息入口交付，连接服务与敏感操作需相应授权，地区和账户开放另核。

收费形式：本轮发布资料未充分确立所有个人套餐收费范围，不能借开发者API价格推定个人代理费用。

产品边界：公司对安全和自主执行的描述属于产品主张，不保证任意任务完成；发布时写作未来的支付或登录整合不能当已开放，地区资格也需确认。

## 需求与市场

### 事实｜当前产品入口已超出历史Llama定位 · 官方资料

本轮访问Llama旧站进入Meta当前开发平台，首页突出Muse模型、编码代理与托管接口，同时仍提供开放权重相关入口。公司目录因此按当前产品组合研究，而不把Meta简单描述为只发布模型权重；历史品牌和模型版本也不会分别增加公司数量。

依据：[Meta当前开发产品入口](<https://dev.meta.ai/>) · [Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

### 判断｜消费者代理和开发者服务面对不同需求 · 研究判断

个人希望把日常任务交给助手，开发者则需要可集成的能力和稳定运行方式。两种需求可能共享模型，却不能由一端的受欢迎程度推定另一端的商业价值；研究应分别观察个人愿意授权什么，以及软件团队愿意承担多少集成与验收工作。

依据：[Meta发布Muse个人代理](<https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/>) · [Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

## 目标用户

### 事实｜编码工具和模型调用面向技术用户 · 官方资料

Muse Code提供终端与持续集成方向的编码工作入口，Model API供团队构建自己的应用，部分权重另可自行部署。这些使用方式需要不同程度的工程能力；能下载权重或安装命令行工具，不等于普通个人已经获得可直接完成全部任务的服务。

依据：[Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

依据：[Meta发布Muse个人代理](<https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/>) · [Meta Model API收费与数据模式](<https://dev.meta.ai/docs/pricing-rate-limits>)

## 产品与工作流

### 事实｜个人Muse使用独立云端任务环境 · 官方资料

发布资料描述Muse在专用虚拟机中运行浏览器和任务，并在涉及发送或购买等敏感动作时请求许可。该设计说明它不只是返回文本，也会产生外部操作；目录将这些作为厂家描述的流程记录，不把专用环境或审批设计直接当成无风险证明。

依据：[Meta发布Muse个人代理](<https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/>)

### 判断｜长任务的交接决定是否能被信任 · 研究判断

用户需要知道代理目前处理到哪里、使用了什么资料、为何请求批准，以及怎样纠正错误目标。持续运行能力可能减少反复提示，却也扩大误解的影响；评估应关注状态与产物可追溯性，而不是只观察模型能否自主执行更多步骤或运行更长时间。

依据：[Meta发布Muse个人代理](<https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/>) · [Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

## 竞争与替代

### 判断｜竞争发生在任务代理和模型基础层 · 研究判断

Meta既与个人助手争夺日常工作入口，也通过Model API和权重路线面对开发平台及自托管方案。社交应用连接可能提供熟悉入口，但不自动降低所有任务的授权成本；比较应看具体资料与执行环境，而不是用已有社交覆盖规模推定代理必然普及。

依据：[Meta当前开发产品入口](<https://dev.meta.ai/>) · [Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

### 验证｜比较托管、编码工具和自运行路线 · 待验证

同一开发任务可以检查直接API、Muse Code和自部署所需工作，比较控制能力、运行资源与维护负担。不同路线的模型或功能可能不完全对等，不能只按标价比较；企业应先确定哪些能力必须保留，再评估迁移与供应商依赖是否可接受。

依据：[Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>) · [Meta Model API收费与数据模式](<https://dev.meta.ai/docs/pricing-rate-limits>)

## 商业模式

### 事实｜数据训练授权会改变价格条件 · 官方资料

官方定价将Standard与Contributor区分，后者以允许内容用于未来模型训练交换优惠或更多用量，且并非每个模型都支持。文档同时说明Muse Code订阅与模式设置相关，因此不能把较低价格和不用于训练两项权益不加条件地同时写入介绍。

依据：[Meta Model API收费与数据模式](<https://dev.meta.ai/docs/pricing-rate-limits>)

### 判断｜低调用价仍需纳入资料和管理成本 · 研究判断

开发者可能被低价吸引，但企业代码、客户资料和第三方内容未必适合贡献模式。商业选择应把资料可用范围、审批、任务复核与持续运行成本一起考虑；本目录不会把折扣推断为长期价格承诺，也不依据厂商宣传测算模型服务利润或客户节约比例。

依据：[Meta Model API收费与数据模式](<https://dev.meta.ai/docs/pricing-rate-limits>) · [Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

## 体验与交付

### 事实｜现成编码代理降低部分启动步骤 · 官方资料

Muse Code把模型调用与计划、文件修改及命令执行组合成工具，并在文档中说明审批和操作系统沙箱。相较自己从API搭建完整代理，它减少了一部分框架工作；但项目依赖、测试环境和允许执行的操作仍需配置，不能理解为安装后所有仓库都可自动交付。

依据：[Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

### 验证｜检查失败时是否容易恢复与退出 · 待验证

体验观察可以覆盖连接失效、任务中断、权限撤销以及不满意输出的修正过程。个人用户和开发者都需要明确的接管方式，尤其在工作跨多个服务时；一段顺畅演示不说明恢复能力，本研究也没有连接私人账号或测试外部执行操作。

依据：[Meta发布Muse个人代理](<https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/>) · [Meta Model API与Muse Code概览](<https://dev.meta.ai/docs/overview>)

创业产品可围绕某类任务提供更明确的输入、授权和验收，而不是只强调个人代理能够处理任何事情。模型和连接入口广泛后，真正差异可能来自领域理解及出错后的处理流程；是否有需求仍需观察用户持续使用和付费意愿，不以平台新发布直接推定。
